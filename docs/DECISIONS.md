# قرارات تقنية — نظام إدارة الحضور والطلبات (نوى)

آخر تحديث: 2026-10-29 · الحالة: معتمدة مبدئياً، بانتظار تأكيد صاحب القرار على البنود في آخر الوثيقة.

## 1. القيد الحاكم: كل شيء مجاني
لا اشتراكات ولا بطاقات دفع. أي مكوّن يتطلب دفعاً يُؤجَّل أو يُستبدل. هذا القيد يحدّد المنصة والتصميم معاً.

## 2. المنصة

| الطبقة | القرار | ملاحظة |
|---|---|---|
| الكود والإصدارات والاختبار الآلي | GitHub (مستودع علني) | لا بيانات ولا مفاتيح داخله إطلاقاً |
| الواجهات | Cloudflare Pages | نشر تلقائي عند كل push |
| الخادم | Cloudflare Workers | حدود المجاني: 100 ألف طلب/يوم، **10 مللي ثانية CPU لكل طلب**، 5 مهام مجدولة، 50 استدعاء خارجي/طلب |
| قاعدة البيانات | Cloudflare D1 | 500 ميغابايت لكل قاعدة، 5 مليون قراءة و100 ألف كتابة يومياً، استرجاع لأي لحظة خلال 7 أيام (Time Travel) |
| الدخول | Microsoft Entra ID (حسابات `nawaculture.org`) | ضمن ترخيص Microsoft 365 الحالي، بلا كلمات سر نديرها |
| بريد الإشعارات | Microsoft Graph من صندوق مخصص | يحتاج صلاحية مدير على المستأجر |
| المرفقات (تقارير طبية) | **مؤجّلة** | R2 يبدو أنه يطلب بطاقة دفع حتى بالمجاني؛ البديل في مرحلته لاحقاً (OneDrive عبر Graph) |
| النسخ الاحتياطي | تصدير ليلي **مشفّر** إلى مستودع **خاص** | المستودع الرئيسي علني، فملفات Actions فيه قابلة للتنزيل من الجميع — لا يُرفع إليه أي تفريغ بيانات |

## 3. أثر قيد الـ 10 مللي ثانية على التصميم (مقيس، لا مفترض)
محرك الحساب يستغرق ~4 ميكروثانية ليوم-موظف واحد، أي ~9 مللي ثانية لشهر كامل لـ 100 موظف، وهذا عند حدّ الطلب الواحد. لذلك:
- نخزّن نتيجة كل يوم-موظف ونعيد حسابها عند كل حركة أو طلب معتمد يخصّه فقط.
- المهمة الليلية (إقفال اليوم وتسجيل الغياب) تعمل على دفعات صغيرة من الموظفين.
- تقارير الشهر والتايم شيت تُحسب في المتصفح بنفس المحرك (هو JavaScript نقي يعمل في الجهتين).

## 4. الصلاحيات
D1 لا يملك Row Level Security، فالصلاحيات تُفرض بالكود. القاعدة: **لا وصول للبيانات إلا عبر طبقة API واحدة**، وفيها دالة تفويض مركزية واحدة، وكل قاعدة دور لها اختبار آلي يعمل على GitHub Actions عند كل تعديل.
الأدوار: موظف · مدير مباشر · موارد بشرية · مدير عام/مفوّض · حارس (جهاز) · مسؤول النظام.

## 5. محرك الحساب (أُنجز: `src/engine/attendance.js`)
نقل حرفي لمنطق ورقة «سجل الدوام اليومي»، ويُثبَّت بالاختبار لا بالثقة:
- **مطابقة إكسل:** 365 يوماً × 17 عموداً (6,205 خلية) من «نموذج تشغيلي مختبَر - مارس 2026» — صفر اختلاف. وتخريب الإعدادات عمداً يكشفه الاختبار.
- 15 اختبار قواعد لحالات لا يغطيها نموذج مارس (التصحيح اليدوي، خروج بلا عودة، حضور بلا انصراف، الإجازات المحتسبة وغير المحتسبة، السماحية عند حدّها).
- كل الأرقام (الدوام، السماحية، العطلة الأسبوعية، أنواع الإجازات) تأتي من الإعدادات، لا شيء مكتوب بالكود.

**سلوكيات إكسل التي نُقلت كما هي عمداً** (تُراجع مع صاحب القرار، ولا تُغيَّر بصمت):
1. دقائق التأخير تُحسب كاملة من بداية الدوام؛ السماحية تغيّر الحالة إلى «متأخر» فقط ولا تُخصم من الدقائق.
2. حضور بلا انصراف ⇒ ساعات التواجد صفر وعجز يوم كامل حتى يُصحَّح يدوياً.
3. خروج بلا عودة ⇒ لا تُحتسب ساعات مغادرة (تنبيه فقط).
4. يوم عطلة فيه حضور ⇒ يظهر «إضافي» بعدد الساعات.

## 6. تعارض في الإعدادات يحتاج حسماً
ملفات إكسل الموجودة عندي تحمل قيماً تخالف ما هو موثّق لديك:

| الإعداد | في الملف | الموثّق |
|---|---|---|
| سماحية التأخير | 15 دقيقة | 10 دقائق |
| العطلة الأسبوعية | الخميس والجمعة والسبت (4 أيام عمل) | الجمعة والسبت |

المحرك لا يتأثر (كلها إعدادات)، لكن القيم الصحيحة لازمة قبل الاستيراد. كذلك يوجد في الملف سقف «المغادرات الشهرية = 6 ساعات» وسيصير قاعدة في وحدة الطلبات.

## 7. المراحل (كل مرحلة تعمل لحالها)
1. **الأساس:** مخطط D1، الدخول، الموظفون والبطاقات والبوابات، استقبال حركات البوابة بنفس صيغة Apps Script الحالية (تبديل رابط فقط)، واستيراد البيانات الحالية. معيار القبول: الشهر نفسه يخرج متطابقاً مع إكسل.
2. **الحساب اليومي:** النتائج اليومية، التصحيحات مع سجل تدقيق، لوحة المتابعة، حالة البوابات.
3. **الطلبات:** مغادرة/عودة/انصراف مبكر/إجازة/مهمة/تصحيح، سلاسل اعتماد، أرصدة، وربط أذونات اليوم بالبوابة.
4. **التقارير:** التايم شيت الشهري بصيغة GIZ مع توزيع المشاريع، والتقارير، وإشعارات البريد.

تجربة موازية على مركز واحد لمدة شهر قبل التعميم؛ البوابة تكتب على Google وعلى النظام الجديد معاً في هذه المدة.

## 8. أسئلة مفتوحة
1. القيم الصحيحة للسماحية والعطلة الأسبوعية (البند 6).
2. هل لكل الموظفين حسابات `nawaculture.org`؟ (غير الحاصلين: تُدخل الموارد البشرية طلباتهم نيابة عنهم.)
3. صلاحية مدير على Microsoft 365 (تسجيل التطبيق وإذن الإرسال) — مطلوبة من المرحلة 3 فقط.
4. لائحة الموارد البشرية: استحقاقات الإجازات، سقوف الأذونات، من يعتمد ماذا.
